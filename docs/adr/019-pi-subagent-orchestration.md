# 019. Unified pi-subagent orchestration

- **Status:** accepted
- **Date:** 2026-09-23

## Context

Generic Role delegation and durable checked implementation graphs share Role, route, executor, evidence, and worktree mechanisms. Separate packages duplicated configuration and exposed overlapping tools. A whole-run wall-clock deadline also expired valid retained work despite finite safety bounds for child operations.

Background direct work previously ran as a separate child process, invisible in Herdr. Moving workers into Herdr tabs makes them visible, but a tab does not isolate files: the shared-checkout writer reservation previously ended when `delegate_task` returned. A non-blocking direct writer could race Main and invalidate its evidence. Herdr lifecycle status alone does not carry an exact final answer into Main's Pi conversation.

## Decision

`@henryqw/pi-subagent` owns both paths behind one explicit `delegate_task` mode:

- `mode: "direct"` runs explicitly authorized bounded tasks with each Role's declared resources, including write-capable tools, in non-focused Herdr tabs in Main's shared checkout. Each direct task declares `access: "read" | "write"` because only the task knows if it writes; every real Role loads a provider extension, so Role capabilities cannot separate readers from writers. `read` is Main's honest, unenforced classification (no sandbox). Only requests with a `write` task acquire checkout writer ownership; read requests run concurrently without admission. They can start only when no direct writer owns the checkout and no Main potentially-writing call is in flight there. Main calls, including all Bash and nested `codemode` writes, do not acquire ownership or block each other; each is tracked separately until its result or execution end, without root or ancestor exceptions. Reads remain available. Write requests serialize tasks and retain Pi checkout admission past tool results, execution end, and session shutdown until exact owned workers are proved stopped (pane absence and two empty private process-lease scans), independently of task success or failure. Uncertain termination retains admission and local recovery authority; `/subagent` Close/cancel-and-release retries only exact locally owned tasks under session/branch/epoch guards, never automatic replay, rollback, or blind unlock. Restart is not termination evidence. It supports single, parallel, and chain tasks, not direct changesets or a separate `background` option.
- `mode: "isolated"` runs durable checked task graphs. Changesets use isolated Herdr worktrees with exact validation, Main-controlled staged integration, and recovery. Requests never silently fall back between modes. Use isolated mode to keep Main free to write, at the cost of worktree checks and explicit integration.

Background execution is a scheduling behavior, not a third `delegate_task` mode. A direct call returns after its first worker is launched; the extension records exact tab identities, observes Herdr lifecycle asynchronously, and verifies a bounded final answer from each worker's Pi session rather than trusting an idle badge or screen contents. An isolated execute/resume acknowledges only after durable state is saved, then continues productive work asynchronously. Workers finish focused preliminary checks and optional judgment before readiness; Main explicitly stages selected candidates in an owned integration checkout via `subagent_stage`, advances dependent work on staged snapshots via `subagent_integrate advance`, validates the combined tip there with the canonical root `pnpm test` suite and optional final judgment, and explicitly promotes only exact passing evidence to Main. A definitive combined failure permits one committed correction and revalidation. Rejected/staged candidates can freeze a generation for explicit restaging; a clean Main advance requires explicit refresh from its new tip, followed by restaging and new combined checks. At most two unreleased integration checkouts can coexist. Main explicitly releases clean superseded generations and rejected terminated workers by exact identity; dirty, conflicted, or uncertain resources stay retained. Exact identities, promotion reconciliation, and conservative post-promotion cleanup safeguard the process. This replaces automatic candidate integration, worker rebase and per-candidate authoritative checks. One exception keeps combined validation exact without a repeated run: a combined check reuses a passed preliminary result only when the combined tree equals a staged candidate's checked tree and the command and argv are identical, and promotion re-verifies that equality from saved identities. Reuse assumes that checks depend on tracked content; ignored files, such as `node_modules`, can differ between worktrees.

A finished direct worker can be continued with `continueFrom` and its direct reference rather than by reusing its tab. The relaunch opens a new tab with Pi `--session` on the saved session file and the same private lease, because a new tab gives exact new identity and the existing termination proof, while the saved session keeps the worker's context. Continuation requires the recorded Role, a terminal exact turn, no local owner, and a proved stop of the old exact idle or done agent; it never closes a working agent. Records without a saved turn identity are not continuable. In read-only workflows, the user can stop one worker from `/subagent`; write workflows keep all-or-nothing Close because admission depends on every owned worker.

The public ephemeral executor is a policy-free mechanism: it receives a prepared Pi launch, runs one bounded task, and returns the result. Direct and isolated modes are extension workflows, not executor primitives. Library callers compose their own workflows with ordinary JavaScript; the package defines no workflow AST. Only pi-subagent parses Roles. A Role owns base tools, extension bundles, Skill names, and an exact MCP server allowlist; callers may add explicit tools, extensions, and environment through `createRoleLaunch`. `resolveConfiguredRoleLaunch` reloads the current Role, package resources, Skill registry, route, and MCP policy for each launch, and the Role system prompt stays separate from prompt-free argv until the final launch boundary. Built-in Roles ship as Markdown in `examples/roles/`, use the user Role parser, and yield to same-named user Roles; the package never writes user configuration. Route precedence is call `modelClass`, then Role `modelClass`, then the caller's Model Task assignment or default. The route owns its thinking level; a direct `model` replaces only the route model.

Completed workflows deliver Pi messages to their launching session with `triggerTurn: true, deliverAs: "followUp"`. A busy Main finishes its current turn before consuming a result; idle Main starts a turn. Session replacement suppresses stale delivery but retains exact recoverable identity. No new daemon or whole-run wall-clock deadline is introduced.

User-confirmed discard from `/subagent` is the one explicit exception to preservation of committed work. The user reviews exact owned resources and confirms permanent deletion of committed, uncommitted, and ignored content. Agents and tools cannot trigger this action.

The command keeps termination, ownership, lease, session, and Herdr pane checks. It deletes only shown resources and branches at their reviewed tips. Saved requests whose parent checkout no longer exists remain available from other checkouts of the same repository through their state-directory addresses. Unreadable state stays preserved.

Execution policy comes only from `config/pi-subagent/config.json`; requests cannot override or replenish limits. Child turn/token/idle/runtime, external I/O, status, termination, and cleanup remain independently bounded. Pi is the Role and model authority; Herdr owns worker tabs and isolated workspaces. The extension stops at Main-authorized checked local integration and never pushes, publishes, deploys, or opens a pull request.

## Explicit independent repository sets

A non-Git workspace can select a set of independent primary repositories by absolute paths. One changeset worker owns a separate worktree in every selected repository. The set, including unchanged members and explicit read-only root inputs, is the validation unit. Scalar identities must not stand in for a repository set.

Workspace state has a separate versioned format and uses existing exact worktree, process-lease, Git stage, and guarded promotion mechanisms. This avoids weakening the existing single-repository state validator. The first workspace contract supports one changeset task and automated checks. It explicitly rejects dependencies, text tasks, and judgment rather than pretending that one repository's evidence covers the others.

Inputs are private copies with content identities. Source or copy drift blocks checks and promotion. Inputs are not promoted as Git changes. The worker's path map and file permissions are not a sandbox.

Main selects the complete candidate set, stages separate integration worktrees, and validates the complete tip set. All Main targets must pass preflight before the first promotion and between serial promotions. Each repository gets a durable intent before its mutation and a receipt before the next mutation. Cross-repository promotion is not atomic. Interruption requires explicit endpoint reconciliation and a separate action to promote remaining targets; no automatic rollback or replay is permitted. Uncertain allocations and prompts remain retained for manual inspection.

Direct selection reserves all selected checkouts and the workspace together through shared process-local admission. One conflicting member refuses the whole reservation. Reporting names each repository; it does not enforce scope. Existing single-repository workflows and saved state remain unchanged when no set is selected.

## Consequences

One package owns delegation. Main continues while workers run visibly in Herdr. Direct writes and commits affect Main immediately and require explicit bounded authorization; they have no isolated validation, rollback, or integration guarantees. Isolated mode remains the checked-worktree workflow. Checkout admission only coordinates this Main's Pi calls; other sessions and external processes remain outside it. Task access declarations are not an OS sandbox, and concurrent changes can make a read stale. A missed delivery or uncertain worker outcome requires status/recovery rather than guessed completion. Rejected candidate resources and superseded checkouts require Main's explicit guarded release; a rejected predecessor can make dependent work impossible within the bounded fresh-attempt rules, requiring a new request. This changed documented automatic integration contract requires a new major pi-subagent release. State v5 rejects v4 and older files rather than migrating them silently. The retired package record remains in [`deprecated/pi-orchestrator`](../../deprecated/pi-orchestrator/README.md).
