# Install dependencies in the background after worktree creation

The `post-checkout` hook validates lockfiles synchronously (so conflicting lockfiles and malformed `packageManager` declarations still fail worktree creation fast), then spawns a detached installer child and exits immediately. The installer records its outcome in `<worktree gitdir>/pi-deps/status.json` with output appended to `install.log` in the same directory. Worktree creation no longer waits for installs; a Pi TUI session opened in the worktree watches the status file and reports progress through a dim footer spinner with elapsed time. Success clears silently; failures remain visible with the installer log path. Keeping normal background work in the footer avoids distracting from the conversation while ensuring failures still demand attention. Blocking creation was rejected because multi-minute frozen installs delayed every `git worktree add`; creator-side integrations were rejected because they miss non-Pi creators.
